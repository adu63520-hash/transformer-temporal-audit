# Same accuracy, different reliance

Code, data generators and run outputs for the paper

> **Same accuracy, different reliance: A controlled audit of temporal order use in Transformers**
> Deli Liu, Xiaoping Zhou, Yu Li (Beijing University of Civil Engineering and Architecture)

The paper asks what can be concluded when a Transformer recovers a physical parameter from a trajectory.
On a task with a closed-form solution it shows that accuracy, reliance on temporal order, and use of the
governing recurrence are three separate properties, and that the common full-permutation test reports
order reliance for a model that was trained without temporal order.

All data are synthetic and are regenerated by the code; no dataset needs to be downloaded.

## Contents

| Path | What it is |
|---|---|
| `tasks.py` | Simulator of the two-stage relaxation chain, tokenisation, the two interventions (hour shuffle, full permutation), least-squares and order-free reference estimators, metrics. NumPy only. |
| `anchors.py` | Reference estimators on both task variants (no neural network). |
| `train_tf.py` | The Transformer regressor, training loop and evaluation. |
| `run_all.py` | Runs the training grid; finished runs are skipped, so it can be resumed. |
| `cue_conflict.py` | Cue-conflict test: trains three models, then evaluates them with the forcing period changed. |
| `summarise_runs.py` | Collects all run outputs into `results/summary.json`. |
| `make_paper_figures.py`, `make_schematic.py` | Produce the figures in `figures/`. |
| `results/` | Outputs of every run reported in the paper (JSON). |
| `figures/` | The figures as PDF and PNG. |

Names used in the code and in file names:

| Code | Paper |
|---|---|
| `orig` | fixed forcing |
| `rand` | random forcing |
| `clean` | trained on clean inputs |
| `time` | trained on hour-shuffled inputs |
| `full` | trained on fully permuted inputs |
| `triple-bag` | order-free ridge |
| `R_time`, `R_full` | hour-shuffle ratio, full-permutation ratio |

## Where each result in the paper comes from

| Paper | Files | Produced by |
|---|---|---|
| Table 1 and the main results figure (fixed forcing, three seeds) | `results/runs/orig_{clean,time,full}_s{0,1,2}.json`, `results/anchors.json` | `anchors.py`, `run_all.py` |
| Table 2 (cue-conflict test) | `results/cue_conflict.json`, `results/runs_ckpt/` | `cue_conflict.py` |
| Table 3 (random forcing, 12,000 steps) | `results/runs/rand_*_long12k.json` | `run_all.py --long` |
| Random forcing at 3,000 steps | `results/runs/rand_{clean,time,full}_s{0,1,2}.json` | `run_all.py` |
| Token-embedding-only variant | `results/runs/*_tokenonly.json` | `run_all.py` |
| Schematic of the interventions | `figures/fig0_interventions.pdf` | `make_schematic.py` |
| Main results figure | `figures/fig1_same_accuracy.pdf` | `make_paper_figures.py` |

`figures/fig2_training_curves.pdf` (training curves under random forcing) is produced by the same script
and is not shown in the journal version.

Each file in `results/runs/` holds the configuration of the run, the evaluation curve during training,
and the final metrics on the in-distribution and out-of-distribution test sets under three input
conditions (`real`, `time`, `full`), including the per-sample predictions on unpermuted inputs.

## Reproducing

Requirements: Python 3.10 or later, NumPy, PyTorch 2.x, Matplotlib (`pip install -r requirements.txt`).
The runs in the paper used Python 3.12.3 and PyTorch 2.11.0 (CUDA 12.6) on one NVIDIA RTX 2080 Ti.

```bash
python anchors.py            # reference estimators, about 10 s on CPU
python run_all.py --smoke    # one-minute check that training works
python run_all.py            # 20 runs of 3,000 steps, about 6 min each on the GPU above
python run_all.py --long     # 4 runs of 12,000 steps, about 22 min each
python cue_conflict.py       # 3 runs of 3,000 steps, then the cue-conflict evaluation
python summarise_runs.py     # writes results/summary.json
python make_paper_figures.py # writes figures/fig1_*, figures/fig2_*
python make_schematic.py     # writes figures/fig0_*
```

To rerun from scratch, delete `results/runs/` first; otherwise existing runs are skipped.

Notes:

- `anchors.py` and the data generators are deterministic and reproduce the stored numbers exactly.
- Training on a GPU is not bit-for-bit reproducible. Re-running a seed gives slightly different numbers;
  for example, the fixed-forcing clean model with seed 0 reached a test error of 0.027 in the main grid
  and 0.030 when it was retrained for the cue-conflict test.
- Model checkpoints are not included. `cue_conflict.py` saves them to `results/ckpt/` when it trains.
- The paper also discusses an earlier protocol of the authors (a frozen language model with a linear
  probe, 35 seeds per condition). The outputs of those runs are not part of this repository.
